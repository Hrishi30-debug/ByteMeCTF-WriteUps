# SoulStone — Reverse Engineering CTF Challenge

## Challenge Information

- **Title:** SoulStone (The Trial of Vormir)
- **Category:** Reverse Engineering
- **Difficulty:** Medium / Hard
- **Player Artifact:** `dist/soulstone` (Single Linux x86-64 stripped binary)
- **Flag Format:** `OWASP{...}`
- **Flag:** `OWASP{a_s0ul_f0r_a_s0ul_v0rm1r_cl1ff_7c8d9e2a}`
- **Offering Solution:** `SOUL{GAMORA:A73D91}`

## Building the Challenge

### Requirements
- `gcc`
- `make`
- `python3`

### Compile Binary
```bash
./build.sh
```
Or via Makefile:
```bash
make build
```

The output binary will be generated at `dist/soulstone`.

### Verification & Testing
```bash
make test
```

### Running the Solvers
- **Python Solver:**
  ```bash
  python3 organizer/solve.py
  ```
- **C Solver:**
  ```bash
  gcc -O3 -o organizer/solve_c organizer/solve.c
  ./organizer/solve_c
  ```
- **Makefile Target:**
  ```bash
  make solve
  ```

## Security & Anti-Shortcut Design

1. **No Plaintext Flag:**
   The flag is nowhere in the binary in plaintext or XOR-only strings.
2. **Cryptographically Authenticated Decryption:**
   The key is required to compute the SHA-256 KDF and verify the HMAC-SHA256 tag over the ciphertext. If any check is bypassed or patched in a debugger, the decryption will produce meaningless random noise.
3. **Controlled Search Space:**
   The resonance token is 24 bits ($16^6 = 16,777,216$ states), perfectly calibrated for a fast, responsive CTF brute-force script (~0.04s in C, ~1–2s in Python).
